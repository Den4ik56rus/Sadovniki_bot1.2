# CRM Roadmap — Sadovniki-bot

**Версия:** 1.0.0
**Создан:** 2025-12-14
**Статус:** В разработке

---

## Обзор

Поэтапное превращение admin-webapp в полноценную CRM-систему для управления клиентами, подписками, поддержкой и аналитикой.

**Текущее состояние admin-webapp:**
- LiveFeed (real-time консультации)
- UserList (список пользователей)
- TopicTimeline (история топиков)
- ConsultationView (детальный просмотр с RAG и cost)
- StatsPanel (статистика по периодам)
- DocumentUpload (загрузка документов)

## Краткое описание этапов

### Этап 0: Подготовка скелета
**Цель:** Зафиксировать единые правила данных и событий.

- Единый словарь статусов (TopicStatus, SupportStage, SubscriptionStatus, ModerationStatus)
- EventLog как отдельный поток событий
- Нормализованный справочник культур/подкультур
- Тест-контур (тестовый бот, песочница оплат)

**Выход:** Можно "проигрывать" путь клиента и видеть события в админке.

---

### Этап 1: Карточка клиента v1
**Цель:** Получить главную пользу — учёт клиентов + история общения.

- Экран "Клиенты" с поиском и фильтрами
- Карточка клиента v1 (базовые данные, список топиков)
- Просмотр переписки внутри топика (read-only)
- Мини-статистика по клиенту

**Выход:** Админка как "CRM-реестр", можно разбирать кейсы без поддержки.

---

### Этап 2: Поддержка (Kanban)
**Цель:** Кейс появляется только по явному нажатию "Поддержка".

- Кнопка "Создать кейс поддержки" в топике/карточке
- Kanban этапы: Новое → В работе → Ждём клиента → Закрыто
- Поля кейса: ссылка на топик, приоритет, ответственный, дедлайн
- Уведомление в Telegram админу при создании кейса

**Выход:** Операционка поддержки заработала.

---

### Этап 3: Подписки/лимиты/деньги
**Цель:** "Сколько принёс и сколько потратил" в карточке и аналитике.

- Блок "Финансы" в карточке (total revenue, LLM cost, маржа)
- Подписка: активна до даты, лимит вопросов, остаток
- Лог списаний по топикам

**Выход:** Появляется экономика и сегментация покупателей.

---

### Этап 4: Покупатели + сегменты
**Цель:** Отдельная вкладка "Покупатели" с готовыми списками.

- Представления: активная подписка, истекает через 7/3/1 день, остаток < 20%, VIP
- Колонки: клиент, тариф, остаток, дата конца, revenue, cost, активность
- Действия: поставить задачу, отправить уведомление

**Выход:** База для удержания и допродаж готова.

---

### Этап 5: AI-выдержки интересов
**Цель:** Профиль интересов клиента для точечных рассылок.

- Запуск при закрытии топика (или по кнопке)
- Сохраняем: культура, категория, 3-7 тегов интересов
- Счётчик частот по тегам/культурам
- Блок "Интересы клиента" в карточке

**Выход:** Основа для "точечной рассылки".

---

### Этап 6: Триггеры + задачи
**Цель:** Автоматизация удержания без риска спама.

- Триггеры: подписка истекает → задача + уведомление админу
- Задачи: чек-лист, дедлайн, статус
- Уведомления в Telegram админам/операторам

**Выход:** CRM начинает работать "сама", но контролируемо.

---

### Этап 7: Реферальная программа
**Цель:** Учёт рефералов и вкладка "Рефералы".

- Механика: referral_code, start payload
- Вкладка: список участников, кто кого привёл, конверсии
- Начисления: пока только учёт (или +N вопросов за реферала)

**Выход:** Канал роста + аналитика по рефералке.

---

### Этап 8: Дашборды v1
**Цель:** Управленческая аналитика без перегруза.

- Общий: пользователи, топики, выручка, cost, маржа
- Воронка: start → бесплатный лимит → оплата
- Поддержка: в очереди, среднее время, просрочки
- Рефералы: регистрации/активации/оплаты

**Выход:** Управление продуктом по цифрам.

---

### Этап 9: Полировка и защита
**Цель:** Стабильность на масштабе.

- Дедупликация событий/уведомлений
- Права доступа (админ/модератор/оператор)
- Аудит-лог изменений
- Экспорт CSV отчётов

**Выход:** Production-ready CRM.

```
Этап 0 (скелет)

    ├── Этап 1 (карточка клиента)
    │       │
    │       ├── Этап 2 (поддержка)
    │       │
    │       └── Этап 3 (финансы)
    │               │
    │               ├── Этап 4 (покупатели)
    │               │
    │               └── Этап 5 (AI интересы)
    │
    └── Этап 6 (триггеры) ←── зависит от Этап 3 + Этап 4
            │
            └── Этап 7 (рефералы)

Этап 9 (полировка) ←── финальный этап
```

## Фичи-стоперы

**Что продумать заранее на каждом этапе:**

1. **Единые ID и связи:**
   ```
   user ↔ topic ↔ messages ↔ support_case ↔ payments ↔ subscription ↔ events
   ```

2. **Статусная модель:**
   - Kanban/модерация/топики не должны конфликтовать
   - См. [DATA_MODELS.md](DATA_MODELS.md)

3. **Антидубли:**
   - Особенно для триггеров и уведомлений
   - Idempotency keys для событий

4. **Справочник культур:**
   - НСД/летняя, ремонтантная и т.д.
   - Нормализация при классификации
